# Submit for review

A review is always about one exact commit. Commit your change, then submit that commit.

<Steps>

<Step>

## Commit

Type a **Commit message** in the form `docs(<section>): <change>`, for example `docs(writing): add the components page`, and choose **Commit source changes**. The console validates the page and answers *Source committed*.

</Step>

<Step>

## Check what you submit

**Review and publication** shows *Review binds this full commit: …* with the commit id, and **Git diff from cloned source** shows every line your branch changes.

</Step>

<Step>

## Submit

Choose **Submit commit for review**. The console answers *Commit submitted for review* and reviewers get a notification under the bell.

</Step>

</Steps>

<Callout type="warning" title="A new commit needs a new review">

If you commit again after submitting, even a one-letter fix, the submission no longer matches the branch. Submit again.

</Callout>

## After the review

- **Approved**: a publisher publishes it. See [Publish the reader site](/docs/docsai/v1/publish-the-reader-site/).
- **Changes requested**: read the reviewer's comment in **Review and publication**, fix, commit and submit again.
