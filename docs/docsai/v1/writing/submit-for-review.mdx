# Submit for review

A review is always about one exact commit. Commit your change, then submit that commit.

<Steps>

<Step>

## Write the commit message

Below the editor, replace the default **Commit message** (*Update guide*) with one line in the form `docs(<section>): <change>`, for example `docs(writing): add the components page`.

![Commit message filled in above Commit source changes](assets/docsai/v1/screenshots/submit-for-review/01-author-commit-message.png)

</Step>

<Step>

## Commit

Choose **Commit source changes**. The console validates the page and answers *Source committed · 〈commit〉*.

![Source committed message with the new commit id](assets/docsai/v1/screenshots/submit-for-review/02-author-source-committed.png)

</Step>

<Step>

## Check what you submit

**Review and publication** shows *Review binds this full commit: … A later commit needs another review.*, and **Git diff from cloned source** shows every line your branch changes.

![Review and publication with the commit the review binds](assets/docsai/v1/screenshots/submit-for-review/03-author-review-binds-commit.png)

</Step>

<Step>

## Submit

Choose **Submit commit for review**. The console answers *Commit submitted for review* and reviewers get a notification under the bell.

![Commit submitted for review message](assets/docsai/v1/screenshots/submit-for-review/04-author-commit-submitted.png)

</Step>

</Steps>

<Callout type="warning" title="A new commit needs a new review">

If anyone commits to the branch after you submit, even a page settings change or an area change by an admin, the submission no longer matches the branch. Submit again.

</Callout>

## After the review

- **Approved**: a publisher publishes it. See [Publish the reader site](/docs/docsai/v1/publish-the-reader-site/).
- **Changes requested**: read the reviewer's comment in **Review and publication**, fix, commit and submit again.
