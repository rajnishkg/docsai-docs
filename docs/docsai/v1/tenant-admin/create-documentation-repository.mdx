# Create a documentation repository

Create a new GitHub repository and its DocsAI project in one step from the console. DocsAI pushes one starter commit with a valid `catalog.json`, so the project opens right away.

You need the **owner** role in the tenant and a verified GitHub connection. See [Connect GitHub](/docs/docsai/v1/connect-github/).

<Steps>

<Step>

## Open Create project

Choose **Repositories**, then **Create project**. The form **Create a DocsAI project** opens: *Choose a configured enterprise Git provider. Creation initializes one starter catalog and branch after you confirm.*

![Create a DocsAI project form in Repositories](assets/docsai/v1/screenshots/create-documentation-repository/01-admin-open-create-project.png)

</Step>

<Step>

## Describe the repository

Fill in the form:

| Field | Example | Notes |
|---|---|---|
| Enterprise provider | GitHub | The connection you verified. It shows **Verified**. |
| Owner / group | `rajnishkg` | The GitHub user or organization that will own the repository. |
| Repository name | `docsai-docs` | Lowercase words joined by hyphens. |
| Project name | `DocsAI docs` | The name people see in the console's **Project** list. |
| Default branch | `main` | Releases are built from this branch. |
| Visibility | Public | **Private**, **Internal** or **Public** on GitHub. Published reader pages are public either way. |

![The form filled in for a public repository named docsai-docs](assets/docsai/v1/screenshots/create-documentation-repository/02-admin-fill-repository-details.png)

</Step>

<Step>

## Create it

Choose **Create project and repository** and confirm the dialog *Create rajnishkg/docsai-docs on GitHub? This will create the remote repository and push one DocsAI template commit.*

After about 20 seconds the new project opens in **Content**, on the default branch, with *Opened exact Git source.*

![The new DocsAI docs project open in Content](assets/docsai/v1/screenshots/create-documentation-repository/03-admin-project-created.png)

</Step>

<Step>

## Check the repository on GitHub

The repository now has one commit, *Initialize DocsAI documentation project*, by *DocsAI project initializer*.

![The new public repository on GitHub with the starter folders](assets/docsai/v1/screenshots/create-documentation-repository/04-reader-github-starter-repository.png)

</Step>

</Steps>

<Callout type="warning" title="QUOTA_EXCEEDED">

When the tenant is over its storage limit, creation stops with *QUOTA_EXCEEDED: This change needs 0 more bytes, but the tenant uses … of its … bytes of storage.* Nothing is created on GitHub. **Settings → Usage and limits** shows the usage; only your platform operator can raise the limit or free storage.

</Callout>

## What the starter commit contains

| Path | Purpose |
|---|---|
| `catalog.json` | The catalog: product `docsai`, version `v1`, the default sections and one starter page. |
| `docs/docsai/v1/getting-started.md` | The starter page. |
| `.github/CODEOWNERS` | Ownership rules. DocsAI maintains the block between `# BEGIN DocsAI areas` and `# END DocsAI areas`. |
| `apis/`, `assets/`, `schemas/`, `playground/`, `manual-sources/` | Folders for API definitions, images, schemas, playground settings and PDF manuals, each with a README. |

## Replace the starter content

To start from your own content, clone the repository, replace the starter files and push one commit to the default branch. These are the commands used to set up this site:

<Tabs groupId="shell" persist="true">

<TabItem value="bash" label="Bash">

```bash
git clone https://github.com/rajnishkg/docsai-docs.git
cd docsai-docs
git rm -q docs/docsai/v1/getting-started.md
# copy catalog.json, README.md, docs/, apis/, assets/ and playground/ into the clone
git add -A
git commit -m "docs(get-started): add the DocsAI user documentation"
git push origin main
```

</TabItem>

<TabItem value="powershell" label="PowerShell">

```powershell
git clone https://github.com/rajnishkg/docsai-docs.git
Set-Location docsai-docs
git rm -q docs/docsai/v1/getting-started.md
# copy catalog.json, README.md, docs/, apis/, assets/ and playground/ into the clone
git add -A
git commit -m "docs(get-started): add the DocsAI user documentation"
git push origin main
```

</TabItem>

</Tabs>

The push answers:

```text title="Output"
To https://github.com/rajnishkg/docsai-docs.git
   36cf3de..4c95954  main -> main
```

Then, in the console, choose **Sync source** and, on the default branch, **Update from published base**, so the project picks up the commit. See [Sync changes from GitHub](/docs/docsai/v1/sync-changes-from-github/).

<Callout type="info" title="Pushing to main skips review">

A direct push to the default branch is fine for the very first content. After that, change content on branches and through review, so every published commit has an approval.

</Callout>
