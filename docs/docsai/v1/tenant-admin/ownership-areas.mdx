# Assign ownership areas

An area makes a team the owner of a folder. Only the team's members, or project owners, can commit inside it, and a reviewer from that team approves changes to it. DocsAI writes the areas to `catalog.json` and keeps a matching block in `.github/CODEOWNERS`.

You need the **owner** role on the project.

<Steps>

<Step>

## Open Area ownership

Choose the project in **Project**, open **Settings** and scroll to **Area ownership**. In **Branch**, enter the branch to commit to, for example `work/author/components-page`, and leave the field: the line below it shows the branch head, here *Branch head 77c814af3dad*, and *No owned areas. Every path needs only the draft permission.*

![Area ownership in Settings with the branch filled in](assets/docsai/v1/screenshots/ownership-areas/01-admin-area-ownership.png)

</Step>

<Step>

## Add an area

Choose **Add area**. Enter the **Path prefix**, a folder ending in `/`, and choose the **Owning team**. In this repository the API team owns the private sample API:

| Path prefix | Owning team |
|---|---|
| `apis/docsai/billing-sample/` | API team (`api`) |

![A new area row with the path apis/docsai/billing-sample/ and the API team](assets/docsai/v1/screenshots/ownership-areas/02-admin-add-area.png)

</Step>

<Step>

## Save

Choose **Save areas and CODEOWNERS**. The console answers *Committed area ownership and .github/CODEOWNERS on work/author/components-page (9ed751e258b1).* Like any commit, it reaches readers only after review and publish, and the author must submit the new head again.

![The saved area and the commit message](assets/docsai/v1/screenshots/ownership-areas/03-admin-areas-saved.png)

</Step>

</Steps>

The result in `catalog.json`:

```json title="catalog.json"
"areas": [
  {"path": "apis/docsai/billing-sample/", "team": "api"}
]
```

and in `.github/CODEOWNERS`, between the DocsAI markers:

```text title=".github/CODEOWNERS"
# BEGIN DocsAI areas
# Generated from catalog.json areas; DocsAI replaces only the lines inside this block.
# /apis/docsai/billing-sample/ owned by DocsAI team api (no provider team)
# END DocsAI areas
```

The API team has no **Provider team** (`org/team`) in **Settings → Teams**, so the line is a comment and GitHub requests no reviewer. Give the team a provider team to turn it into a real `CODEOWNERS` rule.

<Callout type="warning" title="The owning team must approve">

In this repository the commit that added the area needed an approval from the API team too: the reviewer's approval was refused with *AREA_FORBIDDEN: This commit still needs approval from team api.* Before you add an area, make sure a member of the owning team holds the reviewer role on the project. See [Review and approve](/docs/docsai/v1/review-and-approve/).

</Callout>
