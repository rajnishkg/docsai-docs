# Sync changes from GitHub

The console works on its own copy of the repository. When someone commits to the default branch on GitHub, by pushing, merging a pull request or editing a file there, bring that commit into the console with **Sync source**, then into a branch with **Update from published base**.

<Steps>

<Step>

## Sync the source

Sign in with the **publish** permission, choose **Content** and the project. In the **GitHub Enterprise workflow** box, choose **Sync source**.

![The GitHub Enterprise workflow box with Sync source](assets/docsai/v1/screenshots/sync-changes-from-github/01-admin-sync-source.png)

After *Running explicit remote operation…* the console answers *Source synchronized. Existing author branches were retained. Use Update from published base on a branch to bring in the synchronized changes and resolve any conflicts.*

![Source synchronized message under the Sync source button](assets/docsai/v1/screenshots/sync-changes-from-github/02-admin-source-synchronized.png)

</Step>

<Step>

## Update the branch

Sync does not change any branch, not even `main` in the console. Select the branch in **Working branch**, `main` included, and choose **Update from published base**. The console merges the synchronized commit and answers *Branch updated from the published base · 〈commit〉. Submit the new commit for review.*, or that the branch *already contains the published base*.

![Branch updated from the published base on main](assets/docsai/v1/screenshots/sync-changes-from-github/03-author-update-from-published-base.png)

When both sides changed the same lines, the console lists the files to resolve; see [Resolve conflicts](/docs/docsai/v1/resolve-conflicts/).

</Step>

<Step>

## Publish the synchronized change

A sync never changes what readers see. Submit, approve and publish the updated branch like any other change. See [Publish the reader site](/docs/docsai/v1/publish-the-reader-site/).

</Step>

</Steps>

After a pull request is merged on GitHub, the same **Sync source** brings the merge commit in:

![Source synchronized after a pull request was merged on GitHub](assets/docsai/v1/screenshots/sync-changes-from-github/04-admin-sync-after-merge.png)

<Callout type="info" title="The page header can lag behind">

After **Sync source** or a commit, the **Exact branch commit** line at the top can still show the previous commit. Select the branch again in **Working branch** to reload it.

</Callout>

## When sync is refused

Sync only moves forward. It refuses when the console's source and GitHub have diverged, when GitHub's default branch went back in history, or when GitHub is behind a commit the console already published.

**Update from published base** on `main` creates a merge commit that exists only in the console until a later console branch is pushed with **Push & open PR** and merged. Merge that pull request before you commit directly on GitHub's `main`, so GitHub contains everything the console published.
