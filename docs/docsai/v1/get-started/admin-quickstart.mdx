# Admin quickstart

Set up a documentation site for your tenant in five steps. Each step links to the page that shows every click.

You need the **owner** role in your tenant (the `admins` team has it) and a GitHub provider connection set up by your platform operator.

<Steps>

<Step>

## Check the GitHub connection

Open **Settings** and find **Provider connections**, then open **Repositories**, choose **Connect repository** and **Verify provider**. See [Connect GitHub](/docs/docsai/v1/connect-github/).

</Step>

<Step>

## Create the repository

In **Repositories**, choose **Create project**, fill in the owner, repository name, project name and default branch, choose the visibility and select **Create project and repository**. See [Create a documentation repository](/docs/docsai/v1/create-documentation-repository/).

Already have a repository with a `catalog.json`? [Import it](/docs/docsai/v1/import-a-repository/) instead.

</Step>

<Step>

## Give people access

Make sure each person is in a team with the right role, and add project grants where a team needs more on this project. See [Manage users and roles](/docs/docsai/v1/users-and-roles/) and [Assign ownership areas](/docs/docsai/v1/ownership-areas/).

</Step>

<Step>

## Publish the first release

An author submits the commit, a reviewer approves it, and you choose **Publish approved commit to current guides**. See [Publish the reader site](/docs/docsai/v1/publish-the-reader-site/).

</Step>

<Step>

## Keep GitHub and the console in step

When people commit on GitHub, choose **Sync source**. See [Sync changes from GitHub](/docs/docsai/v1/sync-changes-from-github/).

</Step>

</Steps>
